# ADR-003: Reach The Language Model Through A Configured Endpoint And Retry When It Fails

- **Status:** Accepted
- **Created:** 2026-10-22
- **Updated:** 2026-10-25
- **Containers:** `backend`
- **Addresses:** [`FR-002`](../../functional-requirements/fr/FR-002.md), [`QR-01`](../../quality-requirements/qr/QR-01.md), [`QR-04`](../../quality-requirements/qr/QR-04.md)
- **Decision:** [`DEC-024`](../../decisions.md#dec-024)

## Context

The `backend` writes a sentence and a translation for each marked word by calling a language model, and the product must run on a free or cheap model the self-hoster chooses ([`CON-04`](../../product-vision.md#con-04)).
The code is open source, so no key may be committed ([`CON-06`](../../product-vision.md#con-06)).
A free model is overloaded or unreachable from time to time, so the call must survive a model that does not answer without leaving the learner waiting without end.

## Considered Options

- **A configured OpenAI-compatible endpoint, with the key and model name read from `.env`, and a bounded retry.**
  The key, the model name and the base URL come from `.env`, so any compatible model works and none of them is committed; a failed request is repeated a fixed number of times with a growing wait, then the call gives up.
- **A single provider's client library, with the key in the code or a provider-specific setting.**
  Ties the product to one provider and risks the key reaching the repository, against [`CON-04`](../../product-vision.md#con-04) and [`CON-06`](../../product-vision.md#con-06).
- **One request with no retry.**
  Simpler, but a single overloaded response loses the word's sentence, when a short wait and a repeat would have got it.
- **Retry without a limit.**
  Hides an error that a new request cannot fix, such as a bad key, behind an unbounded wait the learner sits through.

## Decision Outcome

Chosen option: an OpenAI-compatible endpoint set by `LLM_BASE_URL`, `LLM_API_KEY` and `LLM_MODEL` in `.env` (`backend/app/config.py`), with the retry in `backend/app/llm.py`.
A request that fails because the model is unavailable is repeated up to 5 requests in all for one word, waiting 1, 2, 4 and 8 seconds plus a random time of up to 1 second, and an error a new request cannot fix is not repeated, per [`DEC-024`](../../decisions.md#dec-024).

## Consequences

- **Security (Confidentiality):** the key is read from `.env`, which is never committed, and it is kept out of the logs and of the error shown to the learner, which keeps [`QR-04`](../../quality-requirements/qr/QR-04.md) reachable.
- **Reliability (Fault Tolerance):** the retry is bounded and a word the model never answers for still gets a card, so the waits for one word end and the learner keeps the word, which keeps [`QR-01`](../../quality-requirements/qr/QR-01.md) reachable.
- **Benefit:** any OpenAI-compatible model works and can be changed in `.env` without code, so the self-hoster picks a free or cheap one.
- **Cost:** a word the model never answers for ends with a card that has no sentence and an error, which the learner retries from the card.
- **Cost:** the key of the server is the only key this record covers, and a request that a user makes from the browser with their own key does not pass through this retry, per [`ADR-004`](ADR-004.md).
