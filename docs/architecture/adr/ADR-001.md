# ADR-001: One React Frontend, One FastAPI Backend, And An SQLite Database

- **Status:** Accepted
- **Created:** 2026-10-22
- **Updated:** 2026-10-22
- **Containers:** `frontend`, `backend`, `database`
- **Addresses:** [`FR-001`](../../functional-requirements/fr/FR-001.md), [`QR-02`](../../quality-requirements/qr/QR-02.md), [`QR-03`](../../quality-requirements/qr/QR-03.md)
- **Decision:** [`DEC-009`](../../decisions.md#dec-009)

## Context

The product takes a learner from a pasted text to studying generated cards, and it must be self-hostable on a local machine or a VPS with a free or cheap language model ([`CON-04`](../../product-vision.md#con-04), [`CON-07`](../../product-vision.md#con-07)).
The team works in Python, and one member has React experience.
The seven weeks of the course must go into the three stories of the minimum usable product rather than into infrastructure.
The split into applications and data stores is the first architectural choice, because every later record names the containers it touches.

## Considered Options

- **A React frontend, a FastAPI backend, and an SQLite database, with the language model outside.**
  Three containers: the pages the learner uses, the API with the scheduler and the model call, and a single-file store.
  FastAPI keeps the API small, React suits the review table where the learner edits, regenerates, flags and deletes many cards at once, and SQLite is one file with no database server.
- **One full-stack framework serving both the pages and the API.**
  Fewer moving parts, but it fits the team's Python skills less well and ties the review table to the framework's own view layer instead of React.
- **A backend with a database server such as PostgreSQL.**
  A server to run and administer, which a learner self-hosting on a local machine or a VPS would have to install and keep running, against [`CON-07`](../../product-vision.md#con-07).

## Decision Outcome

Chosen option: a React (Vite) `frontend`, a FastAPI (Python) `backend`, and an SQLite `database`, with the language model reached as an external system.
It fits the team's skills, keeps the review table on React, and runs as one program with no database server, so a learner can self-host it from `docs/setup.md` alone.
The record documents the customer's and the team's [`DEC-009`](../../decisions.md#dec-009).

## Consequences

- **Maintainability (Testability):** the `backend` is a plain FastAPI application with its logic in modules that `python -m pytest` can run from a clean checkout, which keeps [`QR-02`](../../quality-requirements/qr/QR-02.md) reachable.
- **Flexibility (Installability):** SQLite is one file and no server, so the product runs from `docs/setup.md` on a local machine or a VPS, which keeps [`QR-03`](../../quality-requirements/qr/QR-03.md) reachable.
- **Cost:** three containers must be built, served and documented together, and the `backend` serves the built `frontend` so the product runs as one program for the learner.
- **Cost:** SQLite is a single-writer store, so heavy concurrent writing is not a use the product can take on without revisiting this record.
