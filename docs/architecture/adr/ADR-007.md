# ADR-007: Use OpenObserve As The Analytics Backend

- **Status:** Accepted
- **Created:** 2026-11-07
- **Updated:** 2026-11-07
- **Containers:** `backend`, `database`
- **Addresses:** [`FR-016`](../../functional-requirements/fr/FR-016.md)

## Context

The analytics plan needs a backend that stores the events of each environment, answers the queries that the metrics record, and shows a dashboard for each environment, on the university VM, and it must be self-hosted and open for inspection ([`CON-06`](../../product-vision.md#con-06)).
The course names OpenPanel as the default, and it allows another self-hosted backend when the plan documents it.
The VM has 3.7 GB of memory and no Docker, and OpenPanel is run with Docker and asks for at least 4 GB.
The team also needs a backend for the observability plan, and one program for both is less to run on one VM.

## Considered Options

- **OpenObserve, one program that runs from a folder.**
  It stores events in streams, answers SQL, draws dashboards, keeps each environment in an organization of its own, and takes the events with one HTTP request.
- **OpenPanel, the default.**
  It is made for product analytics, but it needs Docker and about 4 GB of memory, which the VM does not have, so it lost.
- **Tables kept by the team in the product's own database.**
  It needs no new program, but it has no dashboard and mixes the analytics with the cards, and the rules say a metric is read from the pipeline and not from a table the team keeps.

## Decision Outcome

Chosen option: OpenObserve v1.1.2, installed on the university VM as a `systemd` service, with the organizations `analytics_staging` and `analytics_production` for the analytics and `observability_staging` and `observability_production` for the observability.
The `backend` sends each event with one HTTP request, with the user of its own environment, and the dashboards run the queries the plan records.

## Consequences

- **Benefit:** one program on the VM serves the analytics and the observability, within the memory the VM has.
- **Cost:** OpenObserve is a general tool, not a product analytics one, so a metric is a SQL query that the team writes, and it has no ready funnels or retention charts.
- **Cost:** the Enterprise build of the free tier is the one that could be downloaded, and the program was copied to the VM from a computer of the team, so an update is done by hand.
