# FR-015: Keep The Library Of Each Learner Apart, With A Code To Open It Again

- **Status:** Active
- **Traces to:** [`US-12`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/issues/206)
- **Containers:** `frontend`, `backend`, `database`

## Behavior

The product shall keep the texts, the cards and the decks of each learner in a library of their own, which no other learner sees.

The frontend shall make a library code the first time the learner opens the product in a browser, and shall keep it in that browser.

A library code shall be a random version 4 UUID written in lowercase.

The frontend shall send the library code with every request it makes to the backend, in the header `X-Library-Code`.

The backend shall keep each library in a database file of its own, named by its library code.

When a request carries a library code that has no library yet, the backend shall make the library, empty and at the latest version of the tables.

When the backend uses a library that an earlier version of the product made, it shall bring the library to the latest version of the tables before it answers.

The backend shall refuse a request whose library code is not a lowercase UUID, and shall make no file for it.

A request without a library code shall use the default database file of the product, which API tools and tests use.

The frontend shall have a menu "My library" that shows the library code.

The "My library" menu shall let the learner copy the library code.

The "My library" menu shall let the learner save the library code as a text file.

The "My library" menu shall let the learner enter the code of another library.

When the learner enters a code, the product shall say how many cards and decks the library of that code has before it opens it.

When no library has the code that the learner entered, the product shall say so, make no library, and stay in the library the learner is in.

When the learner opens another library, the frontend shall forget the decks ticked on the Study page, because the decks differ.

The product shall not collect the e-mail address of the learner, or any other personal data, to give a library code or to open a library.

## Acceptance Criteria

### AC-01

Given two libraries, when the learner of one makes a deck, then the other library does not have it.

Test: `backend/tests/test_library.py::test_a_library_does_not_show_the_decks_of_another_library`.

### AC-02

Given a library code that no library has, when the product receives a request with it, then it makes the library, empty, in a file named by the code.

Test: `backend/tests/test_library.py::test_a_library_is_its_own_file_next_to_the_default_database`.

### AC-03

Given a library that has a deck and a product that starts again, when a request carries the code of the library, then the deck is still there.

Test: `backend/tests/test_library.py::test_the_same_code_gives_back_the_same_library_after_a_restart`.

### AC-04

Given a library code that is not a lowercase UUID, when a request carries it, then the product refuses it and makes no file.

Test: `backend/tests/test_library.py::test_a_code_that_is_not_a_uuid_is_refused_and_makes_no_file`.

### AC-05

Given a request without a library code, when the product answers, then it uses the default database file and not a library.

Test: `backend/tests/test_library.py::test_a_request_without_a_code_uses_the_default_database`.

### AC-06

Given a browser that has no library code, when the product opens, then it makes a code of the right form, keeps it, and sends it in `X-Library-Code`.

Test: `frontend/src/library.test.js::a new code is a version 4 UUID and differs each time`, `frontend/src/library.test.js::the code is made once and kept in the browser` and `frontend/src/library.test.js::every call carries the code in X-Library-Code`.

### AC-07

Given the "My library" menu, when the learner opens it, then it shows the library code and lets the learner copy it or save it as a file.

Test: `frontend/src/LibraryMenu.test.jsx::the code can be copied` and `frontend/src/LibraryMenu.test.jsx::the code can be saved as a file`.

### AC-08

Given the code of a library that exists, when the learner enters it, then the product says how many cards and decks the library has, and opens it when the learner confirms.

Test: `backend/tests/test_library.py::test_the_library_endpoint_counts_the_cards_and_decks_of_an_existing_library` and `frontend/src/LibraryMenu.test.jsx::a library that exists shows what it has, and opening it changes the code and forgets the ticked decks`.

### AC-09

Given a code that no library has, when the learner enters it, then the product says that there is no library with it, makes no library, and stays in the learner's library.

Test: `backend/tests/test_library.py::test_the_library_endpoint_refuses_an_unknown_code_and_makes_no_library` and `frontend/src/LibraryMenu.test.jsx::a code with no library says so and opens nothing`.

### AC-10

Given a text that is not a code, or the code of the library the learner is in, when the learner enters it, then the product refuses it without asking the backend.

Test: `frontend/src/LibraryMenu.test.jsx::a text that is not a code is refused without asking the product` and `frontend/src/LibraryMenu.test.jsx::the code of the library the learner is in is refused`.

### AC-11

Given two libraries, when the learner opens the second one by its code, then the menu shows the second code and the deck list shows only the decks of the second library.

Checked by hand in the browser with the product running.
