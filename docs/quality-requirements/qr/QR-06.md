# QR-06: No User Ever Sees The Model Key Of Another User

No user of the product can see the model key of another user, so that a teacher never sees the key of a student.

- **Status:** Active
- **Characteristic:** Security
- **Sub-characteristic:** Confidentiality
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A user of the product, such as a teacher, who looks at the data of another user, such as a student.

### Stimulus

The user opens the pages that show the data of another user, such as the cards of a student, or asks the `backend` for that data.

### Environment

A student has set their own model key, a teacher uses the product to review the cards of that student, and the server also holds a key of its own, as [`DEC-038`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/blob/main/docs/decisions.md#dec-038) and [`DEC-040`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/blob/main/docs/decisions.md#dec-040) describe.

### Artifact

The pages that the `frontend` shows and the responses that the `backend` sends for the data of a user: the cards, the texts and the settings.

### Response

The product shall show the key of a user to no other user, in any page, any response or any error.

### Response Measure

In a session where a student has set their own key, every page the teacher opens and every response the teacher receives from the `backend` contain no part of the student's key or of the key of the server, which a search of them for each key value finds zero times.
