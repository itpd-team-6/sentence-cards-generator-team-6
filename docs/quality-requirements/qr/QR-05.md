# QR-05: A Database Schema Update Keeps Every Card The Learner Has

When the database schema is updated, every card the learner already has is kept, and a migration that fails leaves the database at the version it had.

- **Status:** Active
- **Characteristic:** Reliability
- **Sub-characteristic:** Recoverability
- **Business importance:** Medium
- **Technical risk:** High

## Scenario

### Source

A team member who ships a new version of the product with a new migration.

### Stimulus

The product starts against a database file from an earlier version and runs the migrations it has not run yet.

### Environment

A learner's existing database file with cards in it, opened by a product version whose `MIGRATIONS` list is longer than the version the file records.

### Artifact

The migrations and the version number in `backend/app/database.py`.

### Response

The product shall run only the migrations the database has not run, in order, and keep the cards the learner already has; a migration that fails shall leave the database at the version it had, with its cards.

### Response Measure

After a database with cards is opened by a version with a later migration, every card is still present and readable; and if a migration raises, the database version number is unchanged and no card is lost.
