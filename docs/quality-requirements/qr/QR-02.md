# QR-02: The Backend Checks Run From A Clean Checkout And Catch A Broken Critical Module

A developer can run the backend checks from a clean checkout of the repository, and a change that breaks one of the product's critical modules makes those checks fail.

- **Status:** Active
- **Characteristic:** Maintainability
- **Sub-characteristic:** Testability
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A developer on the team, or a reviewer who runs what a pull request claims.

### Stimulus

The developer runs the backend test suite with `python -m pytest` in `backend`, as `CONTRIBUTING.md` says, on a checkout that has no card data of its own.

### Environment

A clean checkout of the repository with the backend environment installed, before any card is created, so the tests set up their own data.

### Artifact

The backend tests in `backend/tests/` and the backend critical modules they cover: `backend/app/scheduler.py` (the due-date rule), `backend/app/database.py` (the migrations and the store), and `backend/app/llm.py` (the model client and its retry and parsing).
`frontend/src/main.jsx` is the frontend entry point and is a critical module as well, but the repository has no frontend tests yet, so no test covers it so far.

### Response

The test suite shall run to completion from the clean checkout and report a pass when the code is correct, and shall report a failure when a critical module's behaviour is broken.

### Response Measure

`python -m pytest` in `backend` passes on the clean checkout, and a change that breaks the scheduler's due-date rule in `backend/app/scheduler.py`, the migration order in `backend/app/database.py`, or the answer parsing in `backend/app/llm.py` makes at least one test fail with a non-zero exit code.

## QRT-01

The whole test suite runs from a clean checkout and fails when a critical module is broken.

- **Status:** Implemented
- **Level:** CI
- **Runs at:** the `Tests` steps of [`.github/workflows/ci.yml`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/blob/main/.github/workflows/ci.yml): the `backend` job runs `python -m pytest` in `backend`, and the `frontend` job runs `npm test` in `frontend`.

### Procedure

On a clean checkout, the `backend` job installs the backend and runs `python -m pytest`, which covers the critical modules [`backend/app/scheduler.py`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/blob/main/backend/app/scheduler.py), [`backend/app/database.py`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/blob/main/backend/app/database.py) and [`backend/app/llm.py`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/blob/main/backend/app/llm.py); the `frontend` job runs `npm test`, which covers the entry point [`frontend/src/main.jsx`](https://github.com/itpd-team-6/sentence-cards-generator-team-6/blob/main/frontend/src/main.jsx). A change that breaks a critical module's behaviour makes at least one test fail.

**Pass when:** both jobs run the suite to completion from the clean checkout and report success, and a break in a critical module makes a test fail with a non-zero exit code.
